9.3

cql: Clinical Quality Language🔗

Clinical Quality Language (CQL) is how health care writes down clinical logic so that a computer can run it and a clinician can still read it: "women aged 50 to 74 with no mammogram in the last two years", "patients whose latest HbA1c is above 9 %". It is the language quality measures and decision-support rules are published in.

This package runs CQL. You write a library, a file of named definitions, and run it over a patient’s record. Each definition gets a value for that patient: true or false, a number, a date, a list of the records that matched. A mistake in the library is reported at its line before anything runs.

Part of the fhir family of FHIR languages and tools.

1 What you can do with it🔗

  • Ask a question of one patient’s record: A first example.

  • Check a library as you write it: every definition is checked against the shape of the data, and a misspelt name is reported with the one you probably meant.

  • Compute a quality measure: which patients count in the denominator and the numerator (Measures).

  • Use a library from a program: as a function from a patient’s data to answers (As a module, from Racket).

  • Work over data that is not FHIR: QI-Core, US Core, QDM, or a model of your own (Data models).

2 A first example🔗

1. Install the tools as the family’s front page describes. The command is then raco cql (or cql, if you built the standalone tools).

2. Have a patient. A patient’s record is a folder of FHIR resources as JSON files. Here it is three files in patient/: the patient, and two HbA1c results (a blood test used to follow diabetes), each naming the patient it belongs to.

{"resourceType": "Patient", "id": "ann", "gender": "female",

 "birthDate": "1974-12-25"}

 

{"resourceType": "Observation", "id": "a1c-1", "status": "final",

 "code": {"coding": [{"system": "http://loinc.org", "code": "4548-4"}]},

 "subject": {"reference": "Patient/ann"}, "effectiveDateTime": "2025-03-01",

 "valueQuantity": {"value": 7.2, "unit": "%",

                   "system": "http://unitsofmeasure.org", "code": "%"}}

The second result is the same with id a1c-2, date 2025-09-01 and value 9.4.

3. Write a library, adults.cql:

library Adults version '1.0.0'

using FHIR version '4.0.1'

include FHIRHelpers version '4.0.1'

 

codesystem "LOINC": 'http://loinc.org'

code "HbA1c": '4548-4' from "LOINC"

 

context Patient

 

define "Female": Patient.gender = 'female'

define "Age": AgeInYears()

define "Adult Female": "Female" and "Age" >= 18

 

define "HbA1c Results": [Observation: "HbA1c"]

define "Tested": exists "HbA1c Results"

define "Highest HbA1c": Max("HbA1c Results" O return (O.value as Quantity).value)

Reading it from the top:

  • using FHIR says the data is FHIR, so the library can talk about Patient and Observation. include FHIRHelpers brings in the standard helper library that lets you compare FHIR values with plain ones (Patient.gender = 'female'). It comes with this package.

  • codesystem and code give a name to the code for an HbA1c test, so the logic below can say "HbA1c" instead of a number.

  • context Patient means every definition is about one patient at a time.

  • Each define names an answer. A definition can use the ones above it: "Adult Female" is built from "Female" and "Age".

  • [Observation: "HbA1c"] is a retrieve: the patient’s Observations with that code. The last line takes the number out of each and keeps the largest.

4. Run it over the patient:

$ raco cql adults.cql --data patient/ --now 2026-01-01 \

    --define "Adult Female" --define "Tested" --define "Highest HbA1c"

Adult Female: true

Tested: true

Highest HbA1c: 9.4

--define picks the answers to print; without it you get every definition, including the two matching Observations in full. --now fixes today’s date, which AgeInYears needs: leave it out and the age is as of today.

5. Make a mistake. Write AgeInYear() and the library is refused, at the place:

$ raco cql adults.cql

adults.cql:11:15: cql compile error: in define "Age": unknown function 'AgeInYear'

  (did you mean `AgeInYears` or `AgeInYearsAt`?)

 11 | define "Age": AgeInYear()

    |               ^^^^^^^^^

Run without --data, a correct library prints its ELM: the form CQL is translated into before it runs, which is what other CQL engines exchange (Words used here).

3 Writing a library🔗

A file is one library: a header, then definitions.

  • The data model. using FHIR version '4.0.1' is what makes [Observation] and O.code mean something. Other models are in Data models.

  • Names. A name with spaces is written in double quotes ("Adult Female"); text is written in single quotes ('female').

  • Retrieves. [Observation] is all of the patient’s Observations; [Observation: "HbA1c"] only those with that code; [Observation: "Diabetes Labs"] those whose code is in a value set you named with valueset "Diabetes Labs": '<its url>'.

  • Queries. "HbA1c Results" O where O.status = 'final' return O.value reads "for each result O, keep the final ones, give its value". sort by, First, Last, Count, Max and the rest work on the list.

  • Parameters. parameter "Measurement Period" Interval<DateTime> declares an input that is given when the library runs.

  • Other libraries. include Common version '1.0.0' called C lets you write C."Some Definition". An included library is looked for beside the file.

  • Nothing there. A missing value is null, and most operations on null give null: comparing a result with no value to 9 is neither true nor false. Coalesce, exists and is null are how you say what should happen then.

Two things catch most newcomers:

  • Forgetting FHIRHelpers. Without include FHIRHelpers, Patient.gender = 'female' compares a FHIR value with a plain one. The library is refused with a message naming the include to add.

  • Dates that can be written two ways. An Observation’s time is either one moment (effectiveDateTime) or a span (effectivePeriod). O.effective during "Measurement Period" reads only the span, so a result with a single moment gives null. Say which you mean: (O.effective as dateTime) during "Measurement Period". The translator warns about this, with the cast to write.

The language itself is described at cql.hl7.org. The repository’s guide.md has a cheat sheet and worked recipes (the latest value per patient, a time window, "never tested"), each one run by the tests.

4 Running it🔗

4.1 Command line🔗

raco cql lib.cql

  

the ELM JSON

raco cql lib.cql --data patient/

  

run it; every definition as name: value

raco cql lib.cql --data bundle.json --define Tested

  

just the named definitions; repeat it

raco cql lib.cql --data p/ --now 2026-01-01

  

what Today() and Now() answer, so a result can be repeated

raco cql lib.cql --data p/ --valuesets vs/

  

ValueSet resources (with expansions) for the library's value sets

raco cql measure.cql --data p/ --libraries libs/

  

includes found as libs/<Name>.cql; else beside the file; else the bundled FHIRHelpers 4.0.1 and 4.4.000

raco cql lib.cql --data p/ --parameter "Measurement Period=Interval[…]"

  

a parameter as a CQL expression; repeat it

raco cql lib.cql --data patient.json

  

a QDM patient document (cqm-models) is one patient's record too

raco cql --tck [-v]

  

the cqframework/cql-tests suite, floor-ratcheted

--data is one patient’s record: a folder of JSON files, one file, or a Bundle. Every mistake in a library is reported, not just the first; --format text|json|outcome chooses the form (text for a person, JSON or a FHIR OperationOutcome for a program). The command exits with 0 when all is well, 1 on a CQL error and 2 when it was called wrongly.

4.2 As a module, from Racket🔗

A CQL file whose first line is #lang cql is a Racket module, so a program can require it and call it. The library is checked when the program is built: a mistake in the CQL stops the build, at its line.

(require json (only-in "adults.cql" evaluate))
(define (read-file f) (call-with-input-file f read-json))
(define record (map read-file '("patient/patient.json" "patient/a1c-1.json" "patient/a1c-2.json")))
(define answers (evaluate record #:now "2026-01-01"))
(hash-ref answers "Adult Female")                           ; #t
(hash-ref answers "Age")                                    ; 51
(evaluate record #:now "2026-01-01" #:define "Tested")      ; #t: one definition

evaluate takes one patient’s records (the Patient among them) and answers every definition by name. #:parameters gives the library’s parameters, #:valuesets the ValueSet resources it needs. The module also provides (results) for a library that reads no data, and the library’s elm. An included library is found beside the file, else among the ones that come with the package (FHIRHelpers).

4.3 Values🔗

The answers are Racket values. Integers, strings and booleans are Racket’s; null is cql-null; lists are lists; a Decimal is fhirpath’s fp-decimal, a Quantity an fp-quantity, a date or time a moment; intervals, tuples, codes and concepts have their own structs (cql/value). render prints any of them the way the command line does.

4.4 The pieces, from Racket🔗

The steps the module form does for you, one at a time: read the text, translate it to ELM, run it.

(require cql/parser/parse cql/compile cql/elm/json cql/run fhir/result/result)
(define lib (ok-value (parse-cql text #:source "adults.cql")))
(elm->json-string (ok-value (compile-library lib)))                   ; the ELM
(evaluate-library lib resources)                                       ; name -> value
; with includes found in a directory (then the bundled ones), parameters as CQL
(define rl (load-runtime-library lib #:resolver (directory-resolver "cql/")
                                     #:data (resources->data resources)
                                     #:valuesets (valuesets->terminology value-sets)
                                     #:parameters (hash "Measurement Period"
                                                        (cql-value "Interval[@2024-01-01T00:00:00Z, @2025-01-01T00:00:00Z)"))))
(rlib-value rl "Tested")

4.5 Measures🔗

A quality measure is a library plus a statement of which of its definitions are the measure’s populations: who is eligible (the denominator) and who met the goal (the numerator). FHIR writes that statement as a Measure resource, and the operation $evaluate-measure runs it and answers a MeasureReport with the counts. It needs somewhere to find the patients, the libraries and the value sets; here, a folder:

(require fhir/operation fhir/data-source cql/measure)
(parameterize ([current-data-source (directory->data-source "ecqm/")])
  (apply-operation "$evaluate-measure" measure
                   #:periodStart "2021-01-01" #:periodEnd "2021-12-31" #:subject "Patient/x"))

Over a server’s store, fhir-server serves the same operation (raco fhir-server evaluate-measure).

A measure in the cqm-models format (a QDM measure document, as Bonnie, MADiE’s QDM side and cqm-execution hold it) is computed by cqm-measure-populations: proportion, ratio, continuous variable and cohort scoring, patient- or episode-based, with strata and observations, the way cqm-execution computes them:

(require cql/run cql/cqm)
(define-values (start end) (cqm-measure-period measure))
(define rl (load-runtime-library main-library #:resolver (directory-resolver dir)
             #:data (resources->data (cqm-patient-records patient) #:patient-context? #f)
             #:valuesets (valuesets->terminology (read-json-files dir)) #:offset 0
             #:parameters (hash "Measurement Period" (cql-value (format "Interval[@~aZ, @~aZ]" start end)))))
(cqm-measure-populations measure rl)
; => (list (hash 'IPP 1 'DENOM 1 'DENEX 0 'NUMER 1)): per population set, then stratum

5 Data models🔗

CQL does not know what a patient record looks like; a data model tells it. The model names the kinds of record (Observation, Encounter …), what each contains, and which element holds its code. A library’s using line picks the model. These come installed:

  • FHIR 4.0.1, the ModelInfo the reference translator ships. Include FHIRHelpers for the implicit conversions between FHIR elements and CQL’s types.

  • QI-Core 4.1.1, 5.0.0, 6.0.0 and US Core 3.1.1, 6.1.0: views over FHIR. A library is typed by their profiles and its ELM reads FHIR, as the reference translator writes it: a retrieve names the FHIR class with the profile as its template; each element with a mapping in the ModelInfo reads through it (FHIRHelpers.ToConcept(C.verificationStatus), an extension or a component as the query that finds it). The data is plain FHIR JSON. QI-Core 4.1.1’s NotDone profiles match a value set both ways: by code, and by the value set the action was not done for.

  • QDM 5.0.2 to 5.6, over cqm-models JSON: a patient document’s dataElements, each naming its class under _type; a Positive…/Negative… retrieve selects the data elements without or with a negationRationale.

You can add a model of your own without writing code. It is two pieces of data: its ModelInfo (the standard description of a model, the same file other CQL tools read) and its representation, which says how its records are written as JSON. 6 In an editor, and for an AI agent🔗

  • In an editor. The family’s language server, fhir-lsp, underlines a library’s mistakes as you type, lists its definitions, jumps from a name to where it is defined (into an included library too) and completes names.

  • For an agent. In an fhir-mcp workspace a library runs over every patient in the data at once, and explain shows why one patient got the answer they did: each definition’s value, down to which records a retrieve kept. The repository’s guide.md is the language written for an agent to read (fhir-mcp serves it as learn://cql), and .claude/skills/cql is the same workflow for an agent using the command line.

7 Limits🔗

  • FHIR version. The FHIR model installed is 4.0.1 (R4). There is none for R5.

  • What a retrieve filters by. The record’s type and its code. A date range written inside a retrieve is not applied (write it as a where), and naming a profile in a retrieve does not filter out records that do not conform to it.

  • One patient at a time. The Patient context applies when the data holds exactly one patient; records are tied to the patient through the links the model declares (in FHIR: subject, patient, performer …).

  • Value sets must be given. Membership is decided from the ValueSet resources you supply: their listed expansion, else the codes they enumerate. A value set defined by a rule ("all descendants of …") is not worked out here, and a value set that is not supplied is an error rather than an empty answer.

  • FHIR Measures. Proportion measures, counted per patient, using the first library and the first group’s populations. Stratifiers, supplemental data and measure observations are not computed, and $evaluate-measure reads measure, periodStart, periodEnd and subject only. (Measures in the cqm-models format get every kind of scoring: cqm-measure-populations.)

  • A definition that does not translate does not stop the rest of its library when the library runs over data: that definition reports its error and the others are answered.

  • QDM versions. A measure written for one version of QDM reads data of another as it is: a QDM 5.3 measure’s principalDiagnosis is simply absent from QDM 5.5 data.

  • ELM is written as JSON only, not XML.

8 Words used here🔗

  • Library: one CQL file: a header and a list of definitions.

  • Definition (a define): a named expression; its value for a patient is an answer.

  • Retrieve: the square-bracket expression that fetches a patient’s records of one kind, [Observation: "HbA1c"].

  • ELM (Expression Logical Model): the standard machine-readable form of a library. CQL is translated to ELM, and the ELM is what runs. Tools exchange it as JSON.

  • Data model, ModelInfo: the description of the records a library talks about. ModelInfo is the standard file format for one.

  • FHIRHelpers: the standard library that converts between FHIR’s values and CQL’s own (a FHIR code and a plain string, a FHIR Quantity and a CQL Quantity).

  • Value set: a named set of codes; code system: where codes come from (LOINC, SNOMED CT).

  • Measure, population: a quality measure and its counted groups: initial population, denominator, numerator, exclusions.

  • QI-Core, US Core: FHIR as profiled for United States quality measurement and interoperability. QDM: the Quality Data Model, an older, non-FHIR model for measures; cqm-models is the JSON format its tools (Bonnie, MADiE, cqm-execution) exchange.

9 How it is tested🔗

Against published work, not only its own examples:

  • HL7’s CQL test suite: 1820 of 1823 expressions give the expected value. The three that do not are places where the suite disagrees with itself.

  • Published libraries, compared definition by definition with the ELM the reference translator produces: 770 of 803 identical for 32 FHIR libraries, 1854 of 2144 for the 98 QI-Core libraries of the 2024 quality measures.

  • Published measures over their own test patients: 71 of 76 for four FHIR measures, 188 of 190 for four QI-Core measures; for QDM, all 31 of cqm-execution’s own checks.

The repository’s TESTING.md names every case that differs and why.
