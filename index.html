cql: Clinical Quality Language for Racket🔗

CQL for Racket. You write a library in a .cql file; it is compiled to ELM (the standard machine form) and the ELM is run over FHIR R4 data: retrieves, value set membership, queries, the implicit FHIRHelpers conversions, and measure populations. A .cql file is a Racket module whose definitions a program evaluates over a patient’s resources.

Held to the published suites: cqframework/cql-tests 1820 of 1823; 32 published libraries compile with 769 of 803 definitions identical to the reference translator’s ELM; four eCQMs agree with their expected populations on 71 of 76 test patients. Part of the fhir family.

1 Quick start🔗

1. Install. The packages are not on the Racket package server yet; clone the repositories side by side and install from source:

raco pkg install --link --auto fhir/fhir fhirpath cql

2. Write a library.

#lang cql

library BloodPressureScreening version '1.0.0'

using FHIR version '4.0.1'

parameter "Panel Codes" List<System.String> default { '85354-9', '55284-4' }

context Patient

 

define "Readings":

  [Observation] O where exists (O.code.coding C where C.code.value in "Panel Codes")

 

define "Systolic Values":

  "Readings" O return singleton from (O.component C

                                        where exists (C.code.coding K where K.code.value = '8480-6')

                                        return (C.value as FHIR.Quantity).value.value)

 

define "Highest Systolic": Max("Systolic Values")

define "Hypertensive": "Highest Systolic" >= 140

3. Run it over a patient’s resources (a directory of FHIR JSON files or Bundles, one Patient among them):

$ raco cql screening.cql --data patient/

Readings: { Observation(...), Observation(...) }

Systolic Values: { 152, 138 }

Highest Systolic: 152

Hypertensive: true

A mistake is reported on its line, naming the definition: screening.cql:12:1: cql compile error: in define "Systolic Values": unknown function ’Mx’. Without --data, raco cql screening.cql prints the ELM JSON.

2 Writing a library🔗

A file is one library: a header, then definitions. using FHIR version ’4.0.1’ loads the FHIR model, so [Observation] retrieves resources and O.code.coding navigates them; context Patient scopes retrieves to one patient; parameter declares an input (with a default); include brings in another library under an alias; valueset "Name": ’url’ makes [Observation: "Name"] a retrieve filtered by membership. Names with spaces are quoted with "…", strings with ’…’. Without FHIRHelpers, FHIR primitives are navigated to their .value; a library that includes FHIRHelpers gets the implicit conversions the reference translator makes. The language reference is cql.hl7.org.

3 Using it🔗

3.1 Command line🔗

raco cql lib.cql

  

the ELM JSON

raco cql lib.cql –data patient/

  

run it; every definition as name: value

raco cql lib.cql –data bundle.json –define Hypertensive

  

just the named definitions

raco cql lib.cql –data p/ –valuesets vs/

  

ValueSet resources (with expansions) for the library's value sets

raco cql measure.cql –data p/ –libraries libs/

  

includes found as libs/<Name>.cql

raco cql –tck [-v]

  

the cqframework/cql-tests suite, floor-ratcheted

--format text|json|outcome chooses how errors are reported (all of them, not just the first). Exit codes: 0, 1 on a CQL error or a suite regression, 2 on usage.

3.2 As a module🔗

(require "screening.cql") compiles the library when the program compiles; a parse or translation error is a compile error positioned in the file. The module provides evaluate, the library over one patient’s resources (the Patient among them), answering every definition’s value by name; (results) for a library with no retrieves; and the library’s elm. Requiring the module also registers it as a Library resource, so measure evaluation finds it by name.

(require (only-in "screening.cql" [evaluate screen]))
(screen (cons patient observations) #:parameters (hash "Panel Codes" '("85354-9" "55284-4")))
; => (hash "Readings" ... "Highest Systolic" 152 "Hypertensive" #t ...)

Resources are FHIR JSON. #:valuesets takes ValueSet resources with expansions.

3.3 Values🔗

Integers, strings and booleans are Racket’s; null is cql-null; lists are lists; a Decimal is fhirpath’s fp-decimal, a Quantity an fp-quantity, a date or time a moment; intervals, tuples, codes and concepts have their own structs (cql/value). render prints any of them the way the command line does.

3.4 From Racket🔗

(require cql/parser/parse cql/compile cql/elm/json cql/run fhir/result/result)
(define lib (ok-value (parse-cql text #:source "screening.cql")))
(elm->json-string (ok-value (compile-library lib)))                   ; the ELM
(evaluate-library lib resources #:parameters (hash "Panel Codes" codes))
; with includes, resolved by name and version
(define rl (load-runtime-library lib #:resolver find-library
                                     #:data (resources->data resources)
                                     #:valuesets (valuesets->terminology value-sets)))
(rlib-value rl "Hypertensive")

3.5 Measures🔗

Measure/$evaluate-measure runs a Measure’s library over a data source holding the patients, the Library resources and the value sets, and answers a MeasureReport:

(require fhir/operation fhir/data-source cql/measure)
(parameterize ([current-data-source (directory->data-source "ecqm/")])
  (apply-operation "$evaluate-measure" measure
                   #:periodStart "2021-01-01" #:periodEnd "2021-12-31" #:subject "Patient/x"))

Over a server’s store, fhir-server serves the same operation (raco fhir-server evaluate-measure).

4 In an editor, for an agent🔗

cql/support is what the family’s language server (fhir-lsp) and MCP server (fhir-mcp) load for CQL: a library’s diagnostics (parse, then every definition translated), the libraries beside it as its project, the declarations as an outline, hover, go to definition (an include alias leads to the library’s file beside it), completion of declared names and keywords, and the tools cql_elm and cql_evaluate. It is a fhir/lang/support value; the hubs know no CQL.

5 Limits🔗

  • Data model. FHIR 4.0.1 only (4.0.0 and an unversioned using FHIR share it); no R5 ModelInfo, no QDM. A retrieve filters by type and code; dateProperty and dateRange are not applied. The Patient context applies when the data holds exactly one Patient, matched by subject, patient and beneficiary references.

  • Terminology. Membership comes from the ValueSet resources supplied: their expansion, else enumerated concepts. Filters and nested value sets are not evaluated and the terminology service is not called; a value set not supplied is an error.

  • Measures. Proportion scoring, patient-based, from the first library and the first group’s population codes; Measure.scoring is not read. No stratifiers, supplemental data or measure observations. $evaluate-measure reads measure, periodStart, periodEnd and subject.

  • The module. evaluate passes no library resolver, so a library with an include runs through load-runtime-library or the command line.

  • ELM is emitted as JSON only. Of 803 definitions in the published corpus, 61 differ from the reference translator in named categories (translator-version noise around InValueSet, choice operands in timing phrases, Interval[…].low re-typing, ratio details in FHIRHelpers, one measure’s day-of-procedure phrases).
